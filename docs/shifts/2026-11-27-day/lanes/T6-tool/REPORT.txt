WHAT A PERSON GETS
The Rules tool (T cycle, between Plants and Command) places a zone and its rules from a preset, ONE batch (one Ctrl+Z):
  1 Start (pad)  2 Checkpoint (pad)  3 Finish (flag)  4 Coin (coin)  5 Door (none)  6 Jump pad (pad)  7 Hazard (none)
  8 Message (none). Two ways in, both on the hotbar's card row and in the side card's text:
  - preset first: 1-8 arms it (slot lit); every click places one on the cell under the cursor, a drag one over the box.
    The same key or 0 stops. The coin trail is "4, click, click, click". While armed the ghost is the preset where it
    would go (rules_layer.preview_node over build.preview), red with the reason when refused (e.g. "Coin refused:
    box: out of range"); a refused preset is never placed.
  - box first (the brief's): with nothing armed, drag (or click) a box, the wheel raises its top, then 1-8.
  The first Start asks the run's name (command_bar field, "Run 1" selected; Enter places, Esc places nothing; the
  closing Enter/Esc neither opens the command bar nor leaves build mode: the stamp tool's latch copied); later Starts
  use it. A Message asks its text the same way.
  Edit: with nothing armed a click on a zone (or on the blocks of a door) selects it (yellow); the side card lists its
  rules as describe() sentences and its knobs: [ ] coin value / door seconds / pad up / message seconds, Shift+[ ] pad
  forward, G run name / message text; Delete or Backspace removes the zone and every rule naming it (one batch).
  With nothing selected the card lists every rule of the Home (12 lines, "and N more") and the run's name.
  Zones show in build mode in every tool (zone_draw.gd: box frame, look icon, name; holo; the selected one yellow),
  hidden in play. Keys used: 0-8, [ ], G, Delete, Backspace, wheel, LMB. None of B, Esc, T, Enter, Ctrl+Z/Y, not E.

PRESETS (rules_tool_presets.gd; every rule built with next_zone_id / next_rule_id)
  start       when you enter Start: start the run <run>
  checkpoint  when you enter Checkpoint N if a run is going: checkpoint at Checkpoint N, say "Checkpoint"
  finish      when you enter Finish if a run is going: finish the run
  coin        when you enter Coin N: take Coin N, add 1 to coins                           (value knob)
  door        the drawn box (the door's BLOCKS, clicked on the wall's face) grown one cell each way through the wall,
              so he stands in it in front and behind. Default (seconds 0): when you press E in Door N: open Door N;
              when you leave Door N: close Door N (no counter). Seconds S (knob 1..30): use if door_<id> is at most
              0: open, add S; every 1 s if door_<id> is 1-1: close, take 1; every 1 s if door_<id> is at least 2:
              open (a no-op on an open zone; it makes the rule name the door so Delete finds it), take 1. Closes
              S-1..S s after E (the every clock's phase), measured 119 frames for S = 2.
  pad         when you enter Jump pad N: launch 10 m/s up, 4 m/s forward                  (up, forward knobs)
  hazard      when you enter Hazard N: back to the respawn
  message     when you enter Message N: say "<text>" (3 s)                                  (text, seconds knobs)
  Zones stand at least 2 cells (start, checkpoint, finish, coin, message) or 1 (door, pad, hazard) unless the wheel set
  the top (then exactly as shown). A knob is offered only while the zone's rules are exactly its preset's (an LLM's or a
  changed rule: Delete only, no knob that would drop its extra effects).

THE FORMAT (stamp_file.gd)
- from_region: course_of(rules layer, lo, hi) gives `zones` (relative boxes, ids 1.. in the Home's id order, saved
  keys only) and `rules` (ids 1.., every zone reference rewritten); any zone or rule makes it tl.stamp/2. Without
  them the stamp is tl.stamp/1 with the v1 keys in the v1 order: the same bytes as before (788 v1 builds the v1 text
  independently and compares the saved file; 756 stamp.* 4/4 unchanged).
- validate: a tl.stamp/1 refuses `zones` / `rules` (unknown key); a tl.stamp/2 needs one of them; each zone and rule
  exactly its saved keys and well formed by rules_check.gd, ids ascending, zone boxes inside the size, every rule
  naming at least one zone and only the stamp's zones, at most 512 each and 8 counters.
- ops: each zone box's two corners turned by turn_cell (the blocks' formula) and sorted, moved to the anchor; the
  rules as `rule` ops with the stamp's ids. placed_ops(build, ...): rules_layer.renumber (read only, unchanged) gives
  the zones and rules the next free ids and rewrites the references: it fitted as is, no PATCHES needed.
- code_of: "TL1-" + base64url without padding of PackedByteArray.compress(COMPRESSION_DEFLATE) of the stamp's text
  (stripped of its newline). Godot's DEFLATE mode writes a zlib stream (RFC 1950: header 0x78, Adler-32 trailer),
  not raw RFC 1951 deflate: see question R1.
- from_code (hostile input): length <= 65,536 after trimming spaces, the prefix, the base64url alphabet, a length
  that is not 1 mod 4, then a zlib header check BEFORE inflating (the engine prints an "ERROR: Decompression failed"
  line for a stream it cannot inflate: seen in the first run of 788), inflate capped at 8 MB, JSON, validate.

BOTH RUNS ARE NOT SEPARATE
- Both copies start the run "Run 1" (the contract keeps the name; records are by name). In play that means one
  record for two courses: a finish on the right one can beat the best time set on the left one, "plays" counts both,
  and a person who changes one copy (a harder jump) still races the other copy's best. It reads as one course that
  happens to exist twice; it stops being honest the moment they differ.
- Proposal (a contract change, not made): when a placed stamp's start names a run the Home already has, the stamp
  tool asks once in the name field, "This course's run is called Run 1, like one you have. Keep the name to share its
  best time, or type a new one", prefilled "Run 1 (2)" and selected: Enter takes the new name, Esc keeps the shared
  one. The rename is done on the ops before they are applied (still one batch). Alternatively records keyed by the
  start zone's place, which survives no move; I would not.
