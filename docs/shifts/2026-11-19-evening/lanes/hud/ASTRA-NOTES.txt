DESIGN AND BEHAVIOUR

Built-in ImageGen produced the two boards before implementation. See concepts/DECISION.md,
split-ticket.jpg, glass-rail.jpg and PROMPTS.txt. Split Ticket separates the race number,
action and timing reference. Glass Rail gave five readings equal weight and lost its
composition when a widget moved.

Parkour reads its instrument catalogue and player layout from data/hud-widgets.json and
data/hud.json. The creator offers seven independently configurable widgets, nine anchor
positions, three sizes and three ink palettes. The preview and the running game share the
same renderer. The preview uses two real, HUD-free course frames and labelled sample
states for the run and finish. The eye toggles and position grid also work without dragging.
Save layout writes only the layout file. Save & play writes it and opens the game in a
window. Reopening the workshop reads back the saved choices. A conflicting external edit
or a validation error is reported without replacing the disk file.

On course the stage, current action, elapsed run, run best and checkpoint punches come
from the live pack. At a timing gate the split slip holds the completed stage for 150
physics ticks. Its signed difference compares that completed stage with its prior best.
A first recorded stage shows FIRST. Between gates it shows live stage time and available
best. Finish lists the four actual splits, each stage best and the best total. Timeout
shows the elapsed time and the stages actually completed. R retains session bests.

Existing TLHud scores, clocks, speeds and free labels receive the house type, measured
stacking and plate treatment. Their existing data sources and text_of values are retained.
The editable catalogue is opt-in. Timber Run supplies one. The workshop discovers other
catalogue-bearing installed games and promoted workbench packs through the same path.
Hockey's game code, scoring rules and HUD sources were untouched.

API 1.11 adds configure_widgets, set_readout and set_phase. The version constant is in
kernel/runner/manifest.gd as required by the brief. API.md documents types, keys and errors.
The house tokens, typeface and OFL licence live in engine/style/hud/ and STYLE.md describes
the visual rules. Archivo moved from the editor into style so both can use one font.
The layout is ordinary pack data. No contract key is needed.
The kernel loads the instrument style on demand. A project made from project.godot
and kernel/ alone imported cleanly, displayed ordinary free/bound label values, and
reported the missing optional module when asked for editable instruments. The probe
printed “HUD kernel only: PASS”.

Windowed QA included the real Play game button. It opened a 1280x720 game worker with
the edited copy's absolute pack path. The test closed that game window normally.
I also inspected the matched six game stills. On the 1080p crop the initial scaled
text had soft edges. The shipped instruments, native labels and editor now request
scale-aware font rasterization. A second 1080p capture confirmed the sharper lettering.

The first visit exposed the village's leave-game hint covering the checkpoint punches.

CODE MAP

engine/kernel/api/tl_hud.gd keeps the existing binding API and installs structured widgets.
engine/style/hud/{stock,layout,sheet,ticket}.gd hold the inks and type, validation, shared
arrangement and drawing. engine/packs/parkour/scripts/main.gd publishes the race readings.
The workbench entry points are engine/ui/host.gd and editor/{village_board,workbench,game_sheet}.gd.
editor/hud/{model,proof,workshop}.gd handle persistence, drag placement and the player UI.
editor/hud/drive.gd produces the clip's real input take. editor/hud/selftest.gd is the
headless input fixture used by engine/tools/selftest.d/550-hud-layout.sh.

hud_stills() {

  done
}
