# Third Life look-test, lane B: inked low-poly with painterly atmosphere

Godot 4.7.2 project (Forward+, Jolt). Everything visible is generated by GDScript at load (about 2 s); there are
no imported assets. Read `REPORT.md` for results, `KIT.md` for the kit, `JOURNAL.md` for the work log.

## Run
```
tools/g.sh import                 # once, and after adding a class_name (the other commands do it automatically)
tools/g.sh cap hero               # -> captures/b_hero.png      (also: site, track, crumble, avatar)
tools/g.sh cap hero --style=overcast --out=hero_overcast
tools/g.sh stats                  # 15 s of the hero view at 2560x1440, prints one JSON line
tools/g.sh movie                  # 20 s -> captures/b_movie.mp4
tools/g.sh run                    # interactive
tools/g.sh play_test              # pass 2: input-driven test, one PASS/FAIL line per assertion
tools/g.sh alt                    # pass 2: hero + site of the second layout (data/layout_alt.json) -> b_alt_hero.png, b_alt_site.png
tools/g.sh compare                # pass 2: pass-1 vs pass-2 sheet -> captures/b_pass2_compare.png
tools/g.sh all                    # the whole acceptance set (captures, alt, play_test, compare, overcast, stats, movie)
```
The contract CLI works directly as well (console exe `C:/Users/kazda/kiro/gtai-spike/tools/godot/Godot_v4.7.2-stable_win64_console.exe`):
```
godot --path . --resolution 1920x1080 res://look.tscn -- --capture=hero [--t=<s>] [--seed=<n>] [--fire=crumble,nitro_pass,site_advance]
godot --path . res://look.tscn -- --capture=crumble --t=1.5 --fire=crumble
godot --path . --resolution 2560x1440 res://look.tscn -- --stats
godot --path . res://look.tscn -- --movie=movie        # relaunches itself with --write-movie --fixed-fps 60, then ffmpeg
godot --path . res://look.tscn -- --capture=hero --style=overcast --out=hero_overcast
```
Windows open at `--position 0,1440` (secondary screen) when started through `g.sh`; set `GPOS` to change it.

## Controls (interactive)
WASD move (camera relative, Shift = run), mouse orbit (click to capture the mouse, Esc releases, wheel = distance
5..8 m, pitch clamped 30..60 degrees), B `crumble`, N `nitro_pass`, H `site_advance`, R `reset`.
Input actions in `project.godot`: move_forward, move_back, move_left, move_right, cam_orbit, crumble, nitro_pass,
site_advance, reset.

## Extra switches (used for the measurements in the report)
`--ink=0` no outline pass, `--grade=0` no grade, `--noshadow`, `--nofog`, `--cam=px,py,pz,lx,ly,lz[,fov]`,
`--anim=walk|run|idle` (hold an avatar clip), `--chase --walk=x,z` (scripted walk with the chase camera),
`--stats --fire=crumble --wait=10` (stats after the wall has settled), `--kitstats` (triangles per part),
extra cameras: `map`, `bot`, `avatar_back`, `avatar_side`.

## Pass 2 additions
- `--layout=<name>` loads `data/layout_<name>.json`; the scene is assembled only from the layout file (`data/layout.json` by default).
- `--play-test` runs the input-driven test; `--nomerge` and `--splits=2` are measurement switches for `--stats`.
- Material classes: `data/style.json` -> `mat.<palette key>.class` = wood | concrete | steel | tarmac | ground | rock | roof | fabric | masonry (+ optional `dscale`, `dk`); global `detail` block. A new material is a palette colour plus one `mat` entry.
- Style values are clamped to looked-at ranges (`style.gd` RANGES); a clamped value prints a `[style]` line.

## Pass 3 additions
- Commands: `tools/g.sh altfull` (five cameras + play test on the alt layout), `tools/g.sh c` (third layout: captures + play test),
  `tools/g.sh faces` (avatar face sheet), `tools/g.sh compare` (pass 2 against pass 3 -> `captures/b_pass3_compare.png`),
  `tools/g.sh pass3` (everything). `tools/g.sh all` is the acceptance set (about 2.5 min on a quiet machine).
- `tools/g.sh` no longer filters Godot's exit-time leak lines (the leak is fixed); `leaked` / `still in use` lines are shown if they return.
- `tools/g.sh movie` waits up to `MOVIE_WAIT` seconds (150) for the process named in `BUSY_EXE` to exit: another GPU process makes
  the movie writer about 10 times slower. `--movie-run=<n> --movie-prof --secs=<s>` prints wall ms per 60 frames.
- One material for the whole palette: every toon surface uses one ShaderMaterial; per-material values come from a lookup texture
  built from `style.json` (`palette` + `mat`). `--permat` restores one material per palette key (measurement switch).
- Switches: `--face=<mood 0..1>,<blink 0..1>` holds the avatar face; camera `face`; `--layout=c`.
- New style keys: `toon.shade_ground`, `toon.shade_grad`, `toon.bounce`, `toon.bounce_k` (shade colour by normal, warm bounce),
  `lights.window`, `lights.window_range`, `lights.mast`, `lights.pool_outer / pool_inner / pool_soft` (banded light pools),
  `detail.macro`, `macro_near`, `macro_far`, `tone_end` (tone pattern that gains contrast with distance), `fx.dust_alpha`, `water.sky_k`.
- New layout keys (all optional): `ridge.fall`, `mesas[].blend / noise`, `waterfalls[] {p, to, w}`, `ridge.ramps[] {c, w, fall}`, `house.ext_side`, `house.frame`,
  `houses[]`, `circuit.wall_blocks`, `arena.rows: 0` (no stands), `forest {density, edges}`, prop kinds `bridge` and `pond`; `river` may be omitted.

## Pass 4 additions
- **Layout contract:** `LAYOUT.md` lists every key a layout file may use (type, default, range, meaning) and what a layout cannot express.
  `tools/g.sh validate <name | path.json> ...` checks a file against it (`tools/validate.gd`, headless; exit code 1 on failure):
  unknown keys are errors, plus types, ranges, required keys, prop kinds, prop arguments, palette keys, cameras and cross-field rules.
- Commands: `tools/g.sh d` (fourth layout `data/layout_d.json`: validator + captures + play test), `tools/g.sh compare`
  (pass 3 against pass 4 -> `captures/b_pass4_compare.png`; concept beside the hero -> `captures/b_pass4_ref.png`),
  `tools/g.sh pass4` (validator on all four layouts + everything `pass3` runs + layout D).
- `BUSY_EXE` (environment variable, **empty by default**): the image name of another GPU process that `tools/g.sh movie` should
  wait for before recording, for up to `MOVIE_WAIT` seconds (150). Example: `BUSY_EXE=SomeBenchmark.exe tools/g.sh movie`.
  Reason: a second GPU-heavy process makes the movie writer about ten times slower. With it empty the movie starts at once
  and prints its recording speed; under about 15 % of real time means something else was using the GPU.
- New style keys: `detail.strata`, `strata_m`, `strata_tone`, `strata_crack` (drawn rock layers on steep terrain),
  `lights.pool_smooth` (share of smooth falloff in a light pool; the pool is now three soft bands with no outer edge).
- Avatar face: one more face bone, `Glints` (eye highlights), so a blink closes fully; 26 bones in all.
- Road kit: skid marks on every bend, a concrete apron with drain slots behind the kerbs, gravel traps on the outside of bends.
- `data/layout_d_frozen.json` is layout D exactly as first written from `LAYOUT.md` with the code frozen.
- New prop kind `watch_tower`; a `pond` prop with the `water` key is still water with a sand shore (both added after the layout-D frozen run).
- New style keys `ink.outer_far`, `ink.thin_near`, `ink.thin_far`: the silhouette line narrows with distance so thin yellow lattices (cranes, scaffolds) keep their colour.
- The play test takes only its own injected mouse motion (device id 77): real pointer motion over the test window no longer changes the result.

## Layout
```
data/layout.json, layout_alt.json, layout_c.json, layout_d.json   the scenes (see LAYOUT.md for the keys)
data/style.json, style_overcast.json   the look (palette, sun, toon bands, fog, sky, ink, grade, holo, water, per-material flags)
data/cams.json                         named cameras
shaders/                               toon (uber), ink_post, sky, grade, holo, glass, water, fx_add, fx_mix
src/mk.gd                              MeshKit primitives
src/kit_*.gd, path.gd, terrain.gd, rig.gd, fx.gd   kit parts (see KIT.md)
src/world.gd                           scene assembly from kit parts at SCENE.md coordinates
src/sim.gd                             cranes, cars + nitro, bots, site_advance, crumble, reset
src/player.gd, look.gd, stage.gd, style.gd   avatar controller + chase camera, modes, light rig, style loader
tools/g.sh, tools/validate.gd (layout validator), tools/patch_style.py
```
No Python packages and no `.venv` are needed (Python is only used by `tools/patch_style.py`, standard library).
